版本v2.3
作者AmpCon Product Team
日期2026-05-07

1. 背景与目标

1.1 背景

AmpCon 融合控制器管理三种网络场景（数据中心、园区、光传输），需要为每个 Site 提供 0-100 的健康度评分来反映网络整体运行状态。

1.2 设计原则

原则说明
三层计算站点健康度 → 设备健康度 → 检查项详情
并列检查各维度独立计算，互不影响
扣分上限每个维度最低 0 分，扣完为止
设备离线特殊处理设备离线时，可用性维度为 0 分，其他维度不计算

2. 计算模型

2.1 三层计算架构

┌─────────────────────────────────────────────────────────────┐
│ Layer 1: 站点健康度                                           │
│                                                              │
│   公式：健康设备数 / 总设备数 × 100                            │
│                                                              │
│   对齐 Cisco：Good 设备数 / 总设备数 × 100%                   │
│                                                              │
│   状态映射：健康(≥90) / 一般(70-89) / 异常(<70)               │
└─────────────────────────────────────────────────────────────┘
                              ↓ 下钻
┌─────────────────────────────────────────────────────────────┐
│ Layer 2: 设备健康度                                           │
│                                                              │
│   设备健康度 = 100 - Σ(各维度扣分)                             │
│                                                              │
│   判定结果：健康(≥90) / 亚健康(70-89) / 不健康(<70)            │
│                                                              │
│   对齐 Cisco：Good(8-10) / Fair(4-7) / Poor(0-3)             │
└─────────────────────────────────────────────────────────────┘
                              ↓ 下钻
┌─────────────────────────────────────────────────────────────┐
│ Layer 3: 设备问题详情                                         │
│                                                              │
│   展示：各维度的扣分明细和具体数值                             │
└─────────────────────────────────────────────────────────────┘

2.2 站点健康度计算（对齐 Cisco）

计算公式 
站点健康度 = 健康设备数 / 总设备数 × 100

定义：

  • 总设备数：站点下所有被纳管的网络设备
  • 健康设备数：Layer 2 判定为"健康"的设备数量

对齐 Cisco：Cisco Catalyst Center 采用 Good 设备数 / 总设备数 × 100% 的计算方式，本方案与其一致。

状态映射

评分区间状态颜色运维建议
90-100健康#10b981 绿色正常巡检
70-89一般#f59e0b 琥珀色安排排查，非紧急
0-69异常#ef4444 红色立即处理

计算示例

场景总设备数健康亚健康不健康健康度状态

2.3 设备健康度计算（对齐 Cisco）

计算公式 
设备健康度 = 100 - Σ(各维度扣分)

每台设备根据以下维度独立评分，各维度扣分互不影响。

设备维度固定分数

每个维度有固定的满分，所有维度满分之和为 100 分：

维度满分说明
设备可用性20 分设备是否在线
设备资源20 分CPU/内存/温度
接口状态20 分接口Up率、错误率
协议状态20 分BGP/EVPN/OSPF
业务指标20 分ECN/PFC/Buffer 等
合计100 分—

与 Cisco KPI 权重对照

Cisco KPICisco 权重本方案维度本方案权重
可达性最高优先级设备可用性20%
CPU 利用率20%设备资源20%
内存利用率20%设备资源（含于 20%）
链路可用性25%接口状态20%
链路错误率15%接口状态（含于 20%）
电源/风扇状态10%设备资源（含于 20%）
温度状态10%设备资源（含于 20%）

设备状态判定标准

状态分数区间颜色判定条件（对齐 Cisco）
健康90-100 分绿色所有维度正常（对齐 Cisco Good: 8-10 分）
亚健康70-89 分琥珀色部分维度扣分但未达到严重程度（对齐 Cisco Fair: 4-7 分）
不健康0-69 分红色任一关键维度严重异常（对齐 Cisco Poor: 0-3 分）

3. 检查项定义

3.1 维度一：设备可用性（满分 20 分，对齐 Cisco "可达性"）

检查项检查方式异常条件扣分结果
设备可达性ICMP 或 SNMP 轮询不可达20 分不健康

规则（对齐 Cisco）：不可达直接判定不健康，其他维度不计算

3.2 维度二：设备资源（满分 20 分，对齐 Cisco KPI 权重 40%）

检查项阈值数据来源异常条件扣分规则
CPU 利用率90%SNMP / Telemetry> 阈值超出 × 0.8 分/%，上限 8 分
内存利用率90%SNMP / Telemetry> 阈值超出 × 0.8 分/%，上限 8 分
温度场景相关SNMP / Telemetry> 阈值超出 × 0.4 分/°C，上限 4 分

温度阈值参考：

场景阈值
数据中心75°C
园区70°C
光传输65°C

说明：此维度合并了 Cisco 的 CPU(20%)、内存(20%)、电源/风扇(10%)、温度(10%) 四个 KPI。

3.3 维度三：接口状态（满分 20 分，对齐 Cisco "链路"权重 40%）

检查项异常条件扣分规则
接口 Down有预期内应 Up 的接口处于 Down 状态每个 × 2 分，上限 12 分
接口错误率错误率 > 1%错误率 × 80，上限 8 分

预期内应 Up 的接口：

  • 已配置且未管理性关闭的接口
  • 已连接设备或链路的接口
  • 排除：未使用的端口、管理性 Down 的端口、预留端口

3.4 维度四：协议状态（满分 20 分，v2.0）

检查项异常条件扣分规则
BGP 会话有 BGP 会话非 Established每个 × 2 分，上限 8 分
EVPN 会话有 EVPN 会话非 Established每个 × 2 分，上限 8 分
OSPF 邻居有 OSPF 邻居非 Full每个 × 1 分，上限 4 分

3.5 维度五：业务指标（满分 20 分，v2.0）

数据中心 AIDC：

检查项阈值扣分规则
ECN 标记率1%超出 × 7 分/1%，上限 7 分
PFC 暂停频率100/min超出 /10 × 0.7 分，上限 7 分
Buffer 利用率80%超出 × 0.6 分/%，上限 6 分

园区（对齐 Cisco Client 健康度）：

检查项阈值扣分规则

4. 因果关系处理

4.1 处理原则

原则一：告警不参与健康度计算

  • 告警有独立的功能模块展示
  • 健康度反映设备客观运行状态
  • 避免因果关系导致的重复扣分

原则二：设备离线特殊处理（对齐 Cisco）

  • 设备离线时，可用性维度 = 0 分
  • 其他维度不计算，按 0 分参与权重计算
  • 这是一种"一票否决"机制，符合 Cisco "不可达直接判定 Poor" 的逻辑

原则三：其他维度并行计算（对齐 Cisco）

  • Cisco 采用各 KPI 独立评分后加权聚合
  • 本方案采用各维度独立扣分后汇总
  • 并行计算能反映问题的叠加效应，不会因为一个维度异常而停止其他维度检查
