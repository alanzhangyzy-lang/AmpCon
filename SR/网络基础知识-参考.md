## 前言：什么是网络？什么是网络工程师？

**Q: 什么是网络？**

A: 网络是将多台计算机/设备通过传输介质和网络设备连接起来，实现数据通信和资源共享的系统。从家里的 WiFi 到全球互联网，本质都是"让设备之间能通信"。

**Q: 什么是网络工程师？**

A: 负责网络的规划、设计、部署、运维和优化的技术人员。核心能力包括：
- 理解网络协议和转发原理
- 设备配置和故障排错
- 网络架构设计
- 安全与性能优化

## 网络概览（全局认知）

### Q1: 在浏览器输入一个网址按回车后，数据经历了哪些步骤才到达对方服务器？

**A:**

完整通信链路：

```
用户输入URL → DNS解析 → TCP三次握手 → HTTP请求 → 数据封装 → 逐跳转发 → 服务器响应
```

| 步骤 | 涉及的协议/机制 | 说明 |
|------|----------------|------|
| 1. 获取本机IP | DHCP | 如果是自动获取地址 |
| 2. 域名解析 | DNS | 将 www.baidu.com 解析为IP地址 |
| 3. 找网关的MAC | ARP | 跨网段通信需要先找到网关MAC |
| 4. 建立连接 | TCP 三次握手 | SYN → SYN+ACK → ACK |
| 5. 发送请求 | HTTP/HTTPS | 封装HTTP请求报文 |
| 6. 数据封装 | 各层协议 | 应用层→传输层→网络层→数据链路层→物理层 |
| 7. 二层转发 | 交换机 MAC表 | 局域网内帧转发 |
| 8. 三层转发 | 路由器 路由表 | 跨网段逐跳转发，每跳改MAC不改IP |
| 9. 到达服务器 | 解封装 | 物理层→数据链路层→网络层→传输层→应用层 |
| 10. 返回响应 | 原路返回 | 服务器回包，经NAT转换回来 |

**关键考点：**
- 跨网段时，源/目的IP不变，源/目的MAC逐跳变化
- 同网段通信直接ARP找目的MAC，不经过路由器
- 如果目的在公网，本机私网IP需要NAT转换

---

### Q2: 为什么网络中需要 IP 地址和 MAC 地址两套地址体系？各自解决什么问题？

**A:**

| 对比项 | MAC 地址 | IP 地址 |
|--------|---------|---------|
| 层次 | 数据链路层 (L2) | 网络层 (L3) |
| 作用范围 | 本地链路（一跳之内） | 端到端（全网路由） |
| 格式 | 48bit，烧录在网卡 | 32bit (IPv4)，逻辑分配 |
| 结构 | 平面结构，无层次 | 层次结构（网络号+主机号） |
| 是否可变 | 硬件固定（一般不变） | 可配置、可变 |
| 类比 | 身份证号（标识唯一设备） | 通信地址（标识所在位置） |

**核心理解：**
- MAC 解决"同一链路内找到对方"的问题——二层寻址
- IP 解决"跨越多个网络找到对方"的问题——三层路由
- MAC是平面的，无法用来做路由选择；IP是层次化的，才能实现路由汇总和分级查找
- 一个管"最后一公里的投递"，一个管"全程的导航"

---

### Q3: 如果把网络比作快递系统，路由器、交换机、IP 地址、MAC 地址分别类比成什么？

**A:**

| 网络概念 | 快递类比 | 说明 |
|---------|---------|------|
| IP 地址 | 收件地址（XX省XX市XX街XX号） | 全局唯一，指明最终目的地 |
| MAC 地址 | 每个中转站的工单号 | 只在本段运输有效，下一段会换新工单 |
| 路由器 | 快递分拨中心 | 看"目的城市"决定下一站是哪个分拨中心 |
| 交换机 | 分拨中心内的分拣员/传送带 | 看"本地工单号"决定从哪个口送出去 |
| 路由表 | 分拨中心的调度表 | "去北京走A口，去上海走B口" |
| 数据包 | 快递包裹 | 外层面单每段换（MAC），快递单不换（IP） |
| NAT | 快递代收点 | 内部地址对外统一用一个公共地址收发 |

### Q4: 什么是协议？为什么网络需要这么多不同的协议？

**A:**

**协议** = 通信双方共同遵守的规则和格式约定。包括三要素：
- **语法**：数据的格式和编码方式
- **语义**：控制信息的含义和要采取的动作
- **时序**：事件的顺序和速率控制

**为什么需要多个协议：**
- 不同层次解决不同问题（物理传输 vs 逻辑寻址 vs 应用服务）
- 分而治之：每个协议专注一件事，降低复杂度
- 可替换性：某一层的协议升级不影响其他层（如从IPv4换IPv6，应用层无感知）
- 多样性需求：不同场景需要不同特性（TCP要可靠、UDP要快速）

---

### Q5: 交换机和路由器的核心区别是什么？各自工作在哪一层？

**A:**

| 对比项 | 交换机 (Switch) | 路由器 (Router) |
|--------|----------------|-----------------|
| 工作层次 | 数据链路层 (L2)，三层交换机工作在L3 | 网络层 (L3) |
| 转发依据 | MAC地址表 | 路由表 (IP地址) |
| 广播域 | 不隔离广播域（每个VLAN是一个广播域） | 隔离广播域 |
| 冲突域 | 每个端口一个冲突域 | 每个端口一个冲突域 |
| 主要功能 | 局域网内部数据帧交换 | 不同网络之间数据包路由转发 |
| 转发速度 | 硬件转发，线速交换 | 软件/硬件转发，相对较慢 |
| 寻址方式 | MAC地址（平面地址） | IP地址（层次化地址） |
| ARP处理 | 泛洪ARP请求 | 代理ARP或路由ARP |

**一句话总结：** 交换机管"同一个网络里面怎么传"，路由器管"去不同网络该走哪条路"。

**关键考点：**
- 二层交换机基于MAC地址转发，不能跨VLAN通信
- 三层交换机 = 二层交换 + 路由功能，通过硬件实现路由转发
- 路由器用于连接不同网段/网络，实现跨网段通信

## 一、物理层与线缆

### Q1: 什么是交换机、路由器、服务器、光模块？它们之间的区别和作用？

**A:**

| 设备 | 是什么 | 作用 | 工作层次 |
|------|--------|------|----------|
| 交换机 | 局域网核心转发设备 | 基于MAC地址转发帧，连接同一网络内的设备 | L2（三层交换机含L3） |
| 路由器 | 网络边界/广域网设备 | 基于IP地址转发包，连接不同网络，隔离广播域 | L3 |
| 服务器 | 高性能计算机 | 运行应用服务（Web/数据库/DNS等），响应客户端请求 | 应用层 |
| 光模块 | 光电转换器件 | 将电信号转为光信号（发送），光信号转为电信号（接收） | L1 物理层 |

**它们的关系：**
- 服务器通过网线/光纤连接交换机
- 交换机负责同网段内的快速转发
- 路由器连接不同网段，实现跨网通信
- 光模块插在交换机/路由器的光口上，实现光纤传输

---

### Q2: 双绞线（T568A/B）、光纤（单模/多模）的区别和应用场景？

**A:**

| 对比项 | 双绞线 (UTP/STP) | 单模光纤 (SMF) | 多模光纤 (MMF) |
|--------|-------------------|----------------|----------------|
| 传输介质 | 铜缆（8芯绞合） | 玻璃纤维 | 玻璃纤维 |
| 传输距离 | ≤100m | 10-80km | ≤550m (OM3/OM4) |
| 最高速率 | 10Gbps (Cat6a) | 100Gbps+ | 100Gbps+ |
| 成本 | 低 | 高（光模块贵） | 中 |
| 纤芯直径 | — | 9μm | 50μm / 62.5μm |
| 光源 | — | 激光 (Laser) | LED / VCSEL |
| 颜色 | — | 黄色护套 | 橙色/水蓝色护套 |
| 典型场景 | 终端接入、办公桌到交换机 | 长距骨干、园区间互联、城域网 | 数据中心内部互联 |

**T568A vs T568B：**
- 两种接线标准，区别在1/2和3/6号线的颜色排列
- T568B更常用（白橙-橙-白绿-蓝-白蓝-绿-白棕-棕）
- 两端相同标准 = 直通线（连不同设备：PC→交换机）
- 两端不同标准 = 交叉线（连相同设备：交换机→交换机）
- 现代设备支持Auto MDI/MDIX自动识别，交叉线已基本淘汰

### Q3: 光模块类型（SFP、SFP+、QSFP28 等）？

**A:**

| 类型 | 速率 | 接口形态 | 典型应用 |
|------|------|----------|----------|
| SFP | 1Gbps | 小型热插拔 | 千兆接入层 |
| SFP+ | 10Gbps | 与SFP相同尺寸 | 万兆汇聚/服务器接入 |
| SFP28 | 25Gbps | 与SFP相同尺寸 | 25G服务器接入 |
| QSFP+ | 40Gbps | 4×10G通道 | 40G核心互联 |
| QSFP28 | 100Gbps | 4×25G通道 | 100G Spine-Leaf互联 |
| QSFP-DD | 400Gbps | 8×50G通道 | 400G数据中心骨干 |

**关键考点：**
- Q = Quad（四通道），通过多通道并行提升速率
- 光模块选型需匹配：速率、距离、光纤类型（单模/多模）
- 同一速率有不同距离规格（如10G SFP+有300m/10km/40km等）

### Q4: 带宽、速率、吞吐量的区别？

**A:**

| 概念 | 含义 | 类比 |
|------|------|------|
| 带宽 (Bandwidth) | 链路的最大传输能力（理论上限） | 高速公路的车道数 |
| 速率 (Speed/Rate) | 接口的标称传输速度（如1Gbps） | 车道的限速标志 |
| 吞吐量 (Throughput) | 实际单位时间内成功传输的数据量 | 实际通过的车流量 |

**核心理解：**
- 吞吐量 ≤ 带宽，实际受协议开销、拥塞、丢包重传等影响
- 一条1Gbps链路的实际吞吐量可能只有700-900Mbps
- 带宽是物理能力，吞吐量是实际表现

## 二、网络分层模型

### Q1: OSI 七层模型每一层的名称和主要职责是什么？

**A:**

| 层次 | 名称 | 职责 | 典型协议/设备 | PDU名称 |
|------|------|------|--------------|---------|
| 7 | 应用层 | 为应用程序提供网络服务接口 | HTTP, FTP, DNS, SMTP | 数据 (Data) |
| 6 | 表示层 | 数据格式转换、加密解密、压缩 | SSL/TLS, JPEG, ASCII | 数据 |
| 5 | 会话层 | 建立/管理/终止会话 | NetBIOS, RPC | 数据 |
| 4 | 传输层 | 端到端可靠传输、流量控制、端口寻址 | TCP, UDP | 段 (Segment) |
| 3 | 网络层 | 逻辑寻址、路由选择、分片重组 | IP, ICMP, OSPF, BGP | 包 (Packet) |
| 2 | 数据链路层 | 帧封装、物理寻址(MAC)、差错检测 | Ethernet, 802.1Q, PPP | 帧 (Frame) |
| 1 | 物理层 | 比特流传输、物理接口和电气规范 | 光纤, 双绞线, 无线电波 | 比特 (Bit) |

**记忆口诀：** 应表会传网数物（All People Seem To Need Data Processing）

---

### Q2: TCP/IP 四层模型和 OSI 七层的对应关系是什么？

**A:**

```
OSI 七层             TCP/IP 四层
─────────────        ─────────────
应用层   ┐
表示层   ├──→       应用层 (Application)
会话层   ┘
传输层   ──→        传输层 (Transport)
网络层   ──→        网际层 (Internet)
数据链路层 ┐
物理层    ┘──→      网络接口层 (Network Access)
```

**关键考点：**
- 实际工程中用TCP/IP四层模型居多，OSI更偏理论参考
- TCP/IP把上三层合并为应用层，下两层合并为网络接口层
- 两个模型不矛盾，是抽象粒度不同

### Q3: 什么是封装和解封装？数据从应用层到物理层经历了哪些变化？

**A:**

**封装（发送方，从上到下）：**
```
应用层数据
  ↓ 加TCP/UDP头（源端口、目的端口、序列号等）
[TCP头 | 数据] = 段 (Segment)
  ↓ 加IP头（源IP、目的IP、TTL等）
[IP头 | TCP头 | 数据] = 包 (Packet)
  ↓ 加帧头帧尾（源MAC、目的MAC、FCS）
[帧头 | IP头 | TCP头 | 数据 | FCS] = 帧 (Frame)
  ↓ 转换为电信号/光信号
比特流 (Bits)
```

**解封装（接收方，从下到上）：** 逆过程，逐层剥离头部。

**核心理解：**
- 每一层只看自己那层的头部，处理完后交给上/下层
- 封装 = 加头（有些层加尾），解封装 = 去头
- 这就是分层的好处：各层独立处理，互不干扰

---

### Q4: 每一层的数据单元叫什么？

**A:**

| 层次 | PDU名称 | 说明 |
|------|---------|------|
| 应用层 | 数据 (Data) / 消息 (Message) | 原始应用数据 |
| 传输层 | 段 (Segment) / 数据报 (Datagram) | TCP用Segment，UDP用Datagram |
| 网络层 | 包 (Packet) | IP数据包 |
| 数据链路层 | 帧 (Frame) | 以太网帧 |
| 物理层 | 比特 (Bit) | 0和1的电/光信号 |

---

### Q5: 为什么要分层？分层的好处是什么？

**A:**

1. **降低复杂度**：把一个大问题分解为多个小问题，各层独立解决
2. **促进标准化**：每层定义清晰接口，不同厂商可独立实现
3. **可替换性**：某层技术升级不影响其他层（如从铜缆换光纤，上层无感知）
4. **方便排错**：逐层定位问题（先查物理层连通性→二层MAC→三层IP→四层端口）
5. **促进竞争和创新**：厂商只需在某层做好就行

## 三、TCP/UDP

### Q1: 什么是TCP？什么是UDP？

**A:**

- **TCP (Transmission Control Protocol)**：传输控制协议，面向连接的可靠传输协议。发送前先建连，传输中确认重传，保证数据完整有序到达。
- **UDP (User Datagram Protocol)**：用户数据报协议，无连接的不可靠传输协议。不建连、不确认、不重传，发了就不管，速度快但不保证送达。

| 对比项 | TCP | UDP |
|--------|-----|-----|
| 连接方式 | 面向连接（三次握手） | 无连接 |
| 可靠性 | 可靠传输（确认、重传） | 不可靠（尽力而为） |
| 有序性 | 保证有序（序列号） | 不保证顺序 |
| 速度 | 较慢（开销大） | 快（开销小） |
| 头部大小 | 20-60字节 | 固定8字节 |
| 流量控制 | 有（滑动窗口） | 无 |
| 拥塞控制 | 有（慢启动等） | 无 |
| 传输方式 | 字节流 | 数据报 |
| 适用场景 | Web浏览、文件传输、邮件 | 视频直播、DNS查询、在线游戏、语音通话 |

---

### Q2: TCP 三次握手 / 四次挥手

**A:**

**三次握手（建立连接）：**
```
Client                    Server
  │──── SYN (seq=x) ────→│    第一次：客户端发起连接请求
  │←── SYN+ACK (seq=y, ack=x+1) ──│    第二次：服务端确认并同步
  │──── ACK (ack=y+1) ──→│    第三次：客户端确认
  │       连接建立完成              │
```

**为什么是三次不是两次？**
- 防止已失效的历史SYN到达服务端后，服务端误建连接浪费资源
- 两次握手服务端无法确认客户端是否真的要建连

**四次挥手（断开连接）：**
```
Client                    Server
  │──── FIN (seq=u) ─────→│    第一次：客户端请求关闭（不再发数据）
  │←── ACK (ack=u+1) ─────│    第二次：服务端确认（但可能还有数据要发）
  │←── FIN (seq=w) ────────│    第三次：服务端也请求关闭
  │──── ACK (ack=w+1) ────→│    第四次：客户端确认
  │   等待2MSL后彻底关闭          │
```

**为什么挥手比握手多一次？**
- TCP是全双工的，每个方向需要独立关闭
- 服务端收到FIN后可能还有数据要发完，所以ACK和FIN分开（不能合并）

---

### Q3: TCP 可靠传输机制

**A:**

| 机制 | 作用 | 说明 |
|------|------|------|
| 序列号 (Seq) | 标识每个字节的编号 | 保证数据有序，检测丢失 |
| 确认应答 (ACK) | 接收方告知发送方已收到 | ACK号 = 期望收到的下一个字节编号 |
| 超时重传 (RTO) | 超时未收到ACK则重发 | RTO动态计算，适应网络状况 |
| 滑动窗口 | 控制发送方发送速率 | 接收方通告窗口大小，实现流量控制 |
| 拥塞控制 | 防止网络过载 | 慢启动→拥塞避免→快重传→快恢复 |
| 校验和 (Checksum) | 检测传输中的数据错误 | 发现错误则丢弃，等待重传 |

---

### Q4: TCP vs UDP 的区别及适用场景

**A:**

**选择TCP的场景（需要可靠）：**
- Web浏览 (HTTP/HTTPS)
- 文件传输 (FTP)
- 电子邮件 (SMTP/POP3/IMAP)
- 远程登录 (SSH/Telnet)
- 数据库访问

**选择UDP的场景（需要快速/实时）：**
- 视频直播/语音通话 (RTP)
- DNS查询（短报文，重传代价小）
- DHCP（客户端还没IP，无法建TCP连接）
- 在线游戏（实时性优先，丢几帧可接受）
- SNMP网络管理
- TFTP简单文件传输

| 23 | TCP | Telnet | 明文远程登录（不安全） |
| 25 | TCP | SMTP | 邮件发送 |
| 53 | TCP/UDP | DNS | 域名解析（查询用UDP，区域传输用TCP） |
| 67/68 | UDP | DHCP | 67服务端，68客户端 |
| 80 | TCP | HTTP | 网页访问 |
| 110 | TCP | POP3 | 邮件接收 |
| 443 | TCP | HTTPS | 加密网页访问 |
| 161/162 | UDP | SNMP | 网络管理 |
| 179 | TCP | BGP | BGP路由协议 |
| 520 | UDP | RIP | RIP路由协议 |

**关键考点：**
- 端口范围 0-65535（16bit）
- 知名端口 0-1023，注册端口 1024-49151，动态/私有端口 49152-65535
- 一个TCP连接由五元组唯一标识：源IP+源端口+目的IP+目的端口+协议号

---

## 四、二层交换

### Q1: 交换机收到一个帧后，是怎么决定从哪个端口转发出去的？

**A:**

**交换机转发决策流程：**
```
收到帧 → 学习源MAC（记录 源MAC + 入端口 到MAC表）
       → 查找目的MAC是否在MAC表中
          → 找到：从对应端口单播转发
          → 找不到：从除入端口外所有端口泛洪 (Flooding)
          → 目的是广播地址：泛洪
          → 目的端口=入端口：丢弃
```

**核心理解：** 交换机是"被动学习，主动转发"。它不需要额外协议来建立MAC表，纯靠观察经过的流量来学习。

---

### Q2: 什么是 MAC 地址表？它是怎么建立起来的？

**A:**

**MAC地址表（也叫CAM表）内容：**

| 字段 | 说明 |
|------|------|
| MAC地址 | 学到的源设备MAC |
| 端口 | 从哪个端口学到的 |
| VLAN | 属于哪个VLAN |
| 类型 | Dynamic（动态学习）/ Static（手动配置） |
| 老化时间 | 默认300秒无流量则删除该条目 |

**建立过程：**
1. 交换机开机时MAC表为空
2. 设备A从端口1发帧 → 交换机记录"A的MAC在端口1"
3. 设备B从端口2回帧 → 交换机记录"B的MAC在端口2"
4. 后续A→B的帧可直接从端口2转发，不再泛洪

---

### Q3: 交换机遇到目的 MAC 不在地址表中时怎么处理？这个行为叫什么？

**A:**

**处理方式：** 泛洪（Flooding）——将帧从除入端口外的所有端口复制转发出去。

**三种转发行为总结：**

| 行为 | 触发条件 | 动作 |
|------|---------|------|
| 转发 (Forward) | 目的MAC在表中，且端口≠入端口 | 从对应端口单播发出 |
| 泛洪 (Flood) | 目的MAC不在表中 / 目的MAC是广播 / 组播 | 除入端口外所有端口发出 |
| 丢弃 (Discard) | 目的MAC对应端口 = 入端口 | 不转发 |

**关键考点：** 泛洪是临时行为——目的设备回帧后，交换机就学到了它的MAC，后续不再泛洪。

---

### Q4: 什么是冲突域？什么是广播域？交换机能隔离哪个？

**A:**

| 概念 | 定义 | 隔离设备 |
|------|------|---------|
| 冲突域 | 共享同一物理介质、可能发生帧碰撞的范围 | 网桥、交换机（每端口一个冲突域） |
| 广播域 | 广播帧能够到达的所有设备的范围 | 路由器 / VLAN |

**不同设备对冲突域和广播域的影响：**

| 设备 | 冲突域 | 广播域 |
|------|--------|--------|
| 集线器 (Hub) | 所有端口共享一个冲突域 | 所有端口在一个广播域 |
| 交换机 (Switch) | 每端口一个冲突域（隔离） | 所有端口在同一广播域（不隔离） |
| 路由器 (Router) | 每端口一个冲突域 | 每端口一个广播域（隔离） |

**核心理解：**
- 交换机能隔离冲突域，但不能隔离广播域
- 要隔离广播域需要路由器或VLAN
- 这就是为什么需要VLAN——在交换机上逻辑隔离广播域

---

### Q5: 为什么说交换是"二层行为"？它依据什么信息做转发决策？

**A:**

- 交换机只看**帧头中的MAC地址**做转发决策，不关心IP
- MAC地址位于OSI第二层（数据链路层），所以交换是"二层行为"
- 交换机不需要理解IP包的内容，对它来说IP包只是帧的载荷（Payload）
- 如果交换机开始看IP地址做转发，那它就变成了三层交换机/路由器

---

## 五、三层路由

### Q1: 什么是路由？路由器的工作原理？

**A:**

**路由**：数据包从源到目的跨越多个网络时，在每个转发节点选择最佳路径的过程。

**路由器工作原理：**
```
收到数据包 → 解封装（去掉二层帧头）→ 查看目的IP地址
           → 查路由表（最长前缀匹配）→ 找到匹配条目
           → 确定下一跳IP和出接口
           → ARP查下一跳的MAC → 重新封装新的帧头（新的源/目MAC）
           → 从出接口转发
```

**关键考点：**
- 路由器每转发一次，都会改变帧头（换MAC），但不改变IP头（源/目的IP不变）
- 路由器是三层设备——它要"拆开帧看IP"才能做转发决策
- TTL（Time To Live）每经过一跳减1，减到0则丢弃（防止环路无限转发）

---

### Q2: 为什么说路由是"三层行为"？它和交换的本质区别在哪？

**A:**

| 对比项 | 二层交换 | 三层路由 |
|--------|---------|---------|
| 转发依据 | MAC地址（帧头） | IP地址（包头） |
| 查找的表 | MAC地址表 | 路由表 / FIB表 |
| 范围 | 同一广播域/网段内 | 跨网段/跨网络 |
| 地址结构 | 平面结构（不可汇总） | 层次结构（可汇总路由） |
| 广播处理 | 泛洪广播帧 | 阻断广播帧 |
| 帧头变化 | 不变 | 每跳改变源/目的MAC |
| IP头变化 | 不变 | TTL减1，其余不变 |

**一句话：** 交换看MAC管本地一跳，路由看IP管全局选路。

---

### Q3: 路由表里一条路由通常包含哪些关键字段？

**A:**

| 字段 | 说明 | 示例 |
|------|------|------|
| 目的网络/掩码 | 要到达的网段 | 10.1.1.0/24 |
| 协议/来源 | 路由怎么来的 | Direct / Static / OSPF / BGP |
| 优先级 (Preference) | 不同来源间选优（值小优先） | Direct=0, Static=60, OSPF=10, BGP=255 |
| 开销 (Metric/Cost) | 同协议内选优（值小优先） | OSPF Cost=10 |
| 下一跳 (Next-Hop) | 下一个路由器的IP | 192.168.1.1 |
| 出接口 (Interface) | 从哪个接口发出 | GE0/0/1 |

**路由选择顺序：**
1. 最长前缀匹配（掩码越长越精确越优先）
2. 优先级（Preference值小优先）
3. 开销（Metric值小优先）

---

### Q4: 直连路由 vs 静态路由 vs 动态路由

**A:**

| 类型 | 产生方式 | 优点 | 缺点 | 适用场景 |
|------|---------|------|------|---------|
| 直连路由 | 接口配IP并UP后自动生成 | 无需额外配置 | 只表示直连网段 | 始终存在 |
| 静态路由 | 管理员手动配置 | 简单可控、不消耗带宽、安全 | 不能自动适应拓扑变化、维护量大 | 小型网络、默认路由、备份路由 |
| 动态路由 | 路由协议自动学习交换 | 自动收敛、适应拓扑变化 | 消耗CPU/带宽、配置较复杂 | 中大型网络 |

**关键考点：**
- 直连路由优先级最高（Preference=0），因为最可信
- 静态路由需要管理员维护，网络变化时要手动修改
- 动态路由协议之间有优先级区别（如OSPF=10, BGP=255）

---

## 六、IP 编址

### Q1: IP 地址的分类（A/B/C/D/E）

**A:**

| 类别 | 首位模式 | 第一字节范围 | 默认掩码 | 网络数 | 用途 |
|------|---------|-------------|---------|--------|------|
| A | 0xxxxxxx | 1-126 | 255.0.0.0 (/8) | 126 | 大型网络 |
| B | 10xxxxxx | 128-191 | 255.255.0.0 (/16) | 16384 | 中型网络 |
| C | 110xxxxx | 192-223 | 255.255.255.0 (/24) | 约200万 | 小型网络 |
| D | 1110xxxx | 224-239 | — | — | 组播地址 |
| E | 1111xxxx | 240-255 | — | — | 保留/实验 |

**特殊地址：**
- 127.0.0.0/8：环回地址（Loopback），测试本机协议栈
- 0.0.0.0：表示"所有网络"或"本机"
- 255.255.255.255：有限广播地址

---

### Q2: 子网掩码的作用

**A:**

**作用：** 区分IP地址中的网络部分和主机部分。

**判断是否在同一网段的方法：**
```
IP地址 AND 子网掩码 = 网络地址
```
两台主机计算出的网络地址相同 → 同一网段（直接二层通信）
网络地址不同 → 不同网段（需经路由器三层转发）

**示例：**
- 192.168.1.10 / 255.255.255.0 → 网络地址 192.168.1.0
- 192.168.1.200 / 255.255.255.0 → 网络地址 192.168.1.0
- 结论：同一网段

---

### Q3: 什么是私网地址？为什么需要私网地址？

**A:**

**私网地址段（RFC 1918）：**

| 类别 | 地址范围 | CIDR表示 | 可用主机数 |
|------|---------|---------|-----------|
| A类私网 | 10.0.0.0 - 10.255.255.255 | 10.0.0.0/8 | 约1678万 |
| B类私网 | 172.16.0.0 - 172.31.255.255 | 172.16.0.0/12 | 约104万 |
| C类私网 | 192.168.0.0 - 192.168.255.255 | 192.168.0.0/16 | 约6.5万 |

**为什么需要私网地址：**
- IPv4地址空间有限（2³² ≈ 43亿），早已不够全球设备使用
- 私网地址可以在不同组织内重复使用，大幅节省公网地址
- 通过NAT技术让私网设备访问公网
- 安全隔离：外部网络无法直接访问私网设备

---

### Q4: 192.168.1.0/26 能划分出几个子网？每个子网有多少个可用主机地址？

**A:**

- 原网络：192.168.1.0/24（8位主机位）
- 子网 /26：从 /24 借了 2 位做子网位
- 子网数 = 2² = **4个子网**
- 每子网主机位 = 32-26 = 6位 → 可用主机 = 2⁶ - 2 = **62个**（减去网络地址和广播地址）

**四个子网详情：**

| 子网 | 网络地址 | 可用范围 | 广播地址 |
|------|---------|---------|---------|
| 1 | 192.168.1.0/26 | .1 - .62 | .63 |
| 2 | 192.168.1.64/26 | .65 - .126 | .127 |
| 3 | 192.168.1.128/26 | .129 - .190 | .191 |
| 4 | 192.168.1.192/26 | .193 - .254 | .255 |

---

### Q5: 什么是 CIDR？它相比传统有类编址有什么优势？

**A:**

**CIDR（Classless Inter-Domain Routing，无类域间路由）：**
- 打破A/B/C类的固定划分界限
- 用任意长度的前缀表示网络：IP/前缀长度（如 10.1.0.0/22）

**相比有类编址的优势：**

| 对比项 | 有类编址 | CIDR |
|--------|---------|------|
| 划分粒度 | 固定（/8, /16, /24） | 任意前缀长度 |
| 地址浪费 | 严重（C类254台，B类6.5万台，不灵活） | 按需分配，浪费少 |
| 路由汇总 | 困难 | 支持超网汇总（缩小路由表） |
| 灵活性 | 差 | 强 |

**示例：** 需要500个地址 → 有类编址必须分配B类（6.5万浪费） → CIDR用/23（512个地址，刚好够用）

---

## 七、VLAN

### Q1: VLAN 是什么？它解决了什么问题？

**A:**

**VLAN（Virtual Local Area Network，虚拟局域网）：** 在一台或多台物理交换机上，逻辑划分出多个隔离的广播域。

**解决的问题：**
- 隔离广播域：减少广播风暴影响范围
- 安全隔离：不同部门/业务的流量互不可见
- 灵活组网：不受物理位置限制（不同楼层可在同一VLAN）
- 简化管理：逻辑分组比物理重新布线方便

---

### Q2: Access / Trunk / Hybrid 端口的区别

**A:**

| 端口类型 | 发送帧处理 | 接收帧处理 | 允许通过的VLAN | 典型连接对象 |
|----------|-----------|-----------|---------------|-------------|
| Access | 剥离VLAN标签后发出 | 给无标签帧打上PVID标签 | 仅PVID一个VLAN | PC、服务器等终端 |
| Trunk | PVID的帧剥离标签，其他VLAN保留标签 | 无标签帧打PVID，有标签帧保留 | allowed-vlan列表中的多个VLAN | 交换机之间互联 |
| Hybrid | 管理员配置决定哪些VLAN剥标签(untagged)哪些保留(tagged) | 无标签帧打PVID，有标签帧保留 | allowed-vlan列表 | 灵活场景（如IP电话+PC） |

**VLAN标签格式（802.1Q）：**
- 在以太网帧的源MAC后插入4字节标签
- TPID (2字节): 固定值 0x8100，标识这是802.1Q帧
- TCI (2字节): Priority (3bit) + CFI (1bit) + VLAN ID (12bit)
- VLAN ID 范围: 0-4095，可用 1-4094

---

### Q3: VLAN 间通信的方式

**A:**

同一VLAN内的设备可直接二层通信；不同VLAN之间隔离，必须通过三层路由才能互通。

| 方式 | 实现 | 优点 | 缺点 |
|------|------|------|------|
| 路由器子接口（单臂路由） | 路由器一个物理口配多个子接口，每个绑定一个VLAN | 设备少时成本低 | 路由器成瓶颈，带宽有限 |
| 三层交换机 VLANIF | 在三层交换机上创建VLANIF虚拟接口作网关 | 硬件线速转发，性能好 | 需要三层交换机 |

**主流方案：** 三层交换机 + VLANIF 接口，每个VLAN对应一个VLANIF接口作为该VLAN的网关。

---

### Q4: Trunk 链路上传输的帧和普通帧有什么不同？

**A:**

- 普通帧（Access口发出）：没有VLAN标签，就是标准以太网帧
- Trunk链路上的帧：携带802.1Q标签（4字节），标明属于哪个VLAN
- 例外：Native VLAN的帧在Trunk上不打标签

```
普通帧: [DMAC | SMAC | Type | Payload | FCS]
带标签: [DMAC | SMAC | 0x8100 | VLAN Tag | Type | Payload | FCS]
```

---

### Q5: 什么是 Native VLAN？为什么需要它？

**A:**

- **Native VLAN**：Trunk端口上，不打802.1Q标签就直接发送的VLAN（默认是VLAN 1）
- **用途**：兼容不支持802.1Q的老设备——这些设备发出的无标签帧会被归入Native VLAN
- **注意事项**：Trunk两端的Native VLAN必须一致，否则会导致VLAN跳跃（VLAN Hopping）安全风险

---

## 八、STP（生成树协议）

### Q1: 如果网络中存在环路，会造成什么后果？

**A:**

| 问题 | 说明 |
|------|------|
| 广播风暴 | 广播帧在环路中无限循环，占满所有带宽，网络瘫痪 |
| MAC地址表震荡 | 同一MAC从不同端口学到，地址表频繁翻转，交换机无法正常转发 |
| 重复帧 | 目的设备收到同一帧的多个副本，上层应用出错 |

**核心理解：** 以太网帧没有TTL字段（不像IP包有TTL会自动消亡），所以一旦成环就永远循环——必须有机制防环。

---

### Q2: STP 是怎么解决环路问题的？基本思路是什么？

**A:**

**基本思路：** 在物理上有环的拓扑中，通过逻辑阻塞某些端口，形成一棵无环的"树"。当活跃链路故障时，再打开被阻塞的端口恢复连通。

**STP 做了三件事（三步选举）：**
1. **选举根桥 (Root Bridge)**：全网选一台交换机作为"树根"
2. **选举根端口 (Root Port)**：每台非根桥交换机选一个离根桥最近的端口
3. **选举指定端口 (Designated Port)**：每条链路选一个转发端口

其余端口被**阻塞 (Blocking)**——不转发数据帧，只收发BPDU。

---

### Q3: STP 中根桥是怎么选举出来的？

**A:**

**选举依据——Bridge ID（桥ID）：**
- Bridge ID = 优先级 (Priority, 16bit) + MAC地址 (48bit)
- 优先级默认 32768，以4096为步长可调
- **Bridge ID最小的成为根桥**

**选举规则：**
1. 先比优先级，值小者优先
2. 优先级相同比MAC地址，值小者优先
3. 所有交换机初始都认为自己是根桥，通过交换BPDU最终收敛

**关键考点：**
- 可通过降低优先级来人为指定根桥
- 根桥的所有端口都是指定端口（都处于转发状态）

---

### Q4: 根端口、指定端口、阻塞端口各自的角色是什么？

**A:**

| 端口角色 | 所在位置 | 选举依据 | 状态 |
|---------|---------|---------|------|
| 根端口 (Root Port) | 每台非根桥上一个 | 到根桥开销最小的端口 | 转发 |
| 指定端口 (Designated Port) | 每条链路上一个 | 该链路上到根桥开销最小的端口 | 转发 |
| 阻塞端口 (Blocking Port) | 其余端口 | 竞争失败的端口 | 阻塞（不转发数据） |

**选择顺序（当开销相同时）：**
1. 比较根路径开销（Root Path Cost）
2. 比较对端桥ID
3. 比较对端端口ID

---

### Q5: RSTP 相比 STP 做了哪些关键改进？

**A:**

| 对比项 | STP (802.1D) | RSTP (802.1W) |
|--------|-------------|---------------|
| 收敛时间 | 30-50秒 | 1-2秒 |
| 端口状态 | 5种 (Disabled/Blocking/Listening/Learning/Forwarding) | 3种 (Discarding/Learning/Forwarding) |
| 快速收敛机制 | 无，依赖定时器 | P/A (Proposal/Agreement) 机制 |
| 边缘端口 | 不支持 | 支持 Edge Port（连终端的端口直接转发） |
| 备份角色 | 无 | Alternate Port（根端口备份）、Backup Port（指定端口备份） |
| 拓扑变更通知 | TC BPDU逐跳传递 | TC位直接在BPDU中通知 |

**RSTP 快速收敛的核心：**
- P/A 机制：上游提议(Proposal) → 下游同步后同意(Agreement)，无需等待定时器
- 边缘端口：连接终端设备的端口标记为Edge，直接进入Forwarding（不经过学习阶段）
- Alternate/Backup端口：故障时立即切换，不需等待

---

### Q6: MSTP 相比 RSTP 的优势是什么？

**A:**

| 对比项 | RSTP | MSTP (802.1S) |
|--------|------|---------------|
| 生成树数量 | 全网一棵树 | 多实例多棵树 |
| VLAN支持 | 所有VLAN共享一棵树 | 不同VLAN映射到不同实例 |
| 负载均衡 | 不能（一条链路阻塞就浪费） | 可以（不同实例阻塞不同链路） |
| 根桥 | 全网一个 | 每个实例独立选举根桥 |

**MSTP核心概念：**
- MST Region（域）：域名 + 修订号 + VLAN-实例映射表 三者相同的交换机构成一个域
- 可以让VLAN 10-20走链路A，VLAN 30-40走链路B，实现流量负载分担

## 九、基础网络服务

### Q1: ARP 解决什么问题？它的工作过程是怎样的？

**A:**

**ARP（Address Resolution Protocol，地址解析协议）：** 已知目的IP地址，解析出对应的MAC地址。

**为什么需要ARP：** 二层转发需要目的MAC地址，但应用层/网络层只知道对方IP。需要一种机制把IP"翻译"成MAC。

**工作过程：**
1. 主机A要发数据给同网段主机B（知道B的IP，不知道B的MAC）
2. 主机A发送**ARP Request**（广播帧，目的MAC=FF:FF:FF:FF:FF:FF）
   - 内容："谁的IP是192.168.1.20？请把你的MAC告诉192.168.1.10"
3. 同网段所有设备收到，但只有IP匹配的主机B回复
4. 主机B发送**ARP Reply**（单播帧，直接回给A）
   - 内容："192.168.1.20的MAC是 AA:BB:CC:DD:EE:FF"
5. 主机A收到后记入**ARP缓存表**（有老化时间），后续发送直接查表不再广播

---

### Q2: 免费ARP（Gratuitous ARP）的用途

**A:**

**免费ARP**：主机发出的目标IP = 自己IP 的ARP请求。

**用途：**
1. **地址冲突检测**：如果收到回复，说明有人用了相同IP → 地址冲突
2. **通告地址变更**：MAC地址变了（如网卡更换），通过免费ARP让其他设备更新ARP缓存
3. **VRRP主备切换**：新Master发免费ARP，让下游设备更新虚拟IP对应的MAC

---

### Q3: ARP 代理的场景

**A:**

**ARP代理（Proxy ARP）：** 路由器代替目标设备回复ARP请求。

**应用场景：**
- 两台主机在不同网段，但主机没有配网关（或不知道要走网关）
- 主机A广播ARP请求"谁是10.1.1.100"，路由器发现自己知道去10.1.1.0/24的路由
- 路由器用自己的MAC回复ARP，让A把帧发给路由器，路由器再转发给真正目的

**注意：** 生产环境一般关闭ARP代理，因为会隐藏网络拓扑，增加排错难度。

---

### Q4: ARP 欺骗/攻击原理

**A:**

**攻击原理：**
- ARP协议没有认证机制——收到ARP Reply就直接更新缓存
- 攻击者C伪造ARP Reply告诉A："B的IP对应的MAC是C的MAC"
- A的ARP缓存被篡改，后续发给B的流量全部送到C → 中间人攻击

**防范手段：**
- **DAI (Dynamic ARP Inspection)**：交换机检查ARP报文合法性
- **DHCP Snooping绑定表**：只有绑定表中的IP-MAC映射才允许通过
- **静态ARP绑定**：关键设备（如网关）绑定静态ARP条目

---

### Q5: DHCP 的四步交互过程（DORA）

**A:**

```
Client                    Server
  │── DHCP Discover ───→│  (广播) 客户端找DHCP服务器
  │←─ DHCP Offer ───────│  (单播/广播) 服务器提供IP地址
  │── DHCP Request ────→│  (广播) 客户端选择并请求该IP
  │←─ DHCP ACK ─────────│  (单播/广播) 服务器确认分配
```

| 报文 | 方向 | 说明 |
|------|------|------|
| Discover | 客户端→广播 | "有没有DHCP服务器？我需要一个IP" |
| Offer | 服务器→客户端 | "我是X服务器，给你分配192.168.1.10" |
| Request | 客户端→广播 | "我选择X服务器给的地址"（广播让其他服务器知道） |
| ACK | 服务器→客户端 | "确认，192.168.1.10归你了，租约XX小时" |

**为什么Discover和Request是广播？**
- Discover：客户端还没IP，不知道服务器在哪
- Request：通知其他DHCP服务器"我已选了别人的Offer，你们可以收回"

---

### Q6: DHCP Relay 的作用和工作原理

**A:**

**问题：** DHCP Discover是广播包，路由器不转发广播 → 如果DHCP服务器不在同一网段，客户端找不到服务器。

**解决：** 在客户端网关上配置**DHCP Relay（中继）**。

**工作原理：**
1. 客户端广播Discover
2. Relay Agent（网关）收到后，将报文转为单播，填入giaddr（Relay的接口IP），转发给指定的DHCP服务器
3. 服务器根据giaddr判断客户端在哪个网段，分配对应地址池的IP
4. 服务器单播回给Relay，Relay再转给客户端

---

### Q7: DHCP Snooping 的作用

**A:**

**DHCP Snooping**：交换机上的DHCP安全机制。

**作用：**
- 防止非法DHCP服务器（Rogue DHCP Server）：只有受信端口（Trust）才能发送DHCP Offer/ACK
- 建立绑定表（IP-MAC-端口-VLAN映射）：后续用于DAI、IP Source Guard等安全功能
- 非信任端口只允许发送DHCP Request，不能发Offer

---

### Q8: DNS 的作用和查询流程

**A:**

**DNS（Domain Name System，域名系统）：** 将人类可读的域名翻译为IP地址。

**递归查询 vs 迭代查询：**

| 类型 | 过程 | 用在哪 |
|------|------|--------|
| 递归查询 | 客户端问本地DNS服务器，服务器负责查到底返回最终结果 | 客户端 → 本地DNS |
| 迭代查询 | 被询问者不知道答案时返回下一个应该问谁（referral） | 本地DNS → 根/顶级/权威DNS |

**完整查询流程：**
```
客户端 →(递归)→ 本地DNS服务器 →(迭代)→ 根DNS → 顶级域DNS (.com) → 权威DNS (baidu.com)
                                        ←─ 返回最终IP ──┘
         ←─ 将结果返回给客户端 ──┘
```

---

### Q9: NAT 的作用和类型

**A:**

**NAT（Network Address Translation，网络地址转换）：** 将私网IP地址转换为公网IP地址，实现私网设备访问互联网。

**为什么需要NAT：** 私网地址不能在公网路由（公网路由器不识别私网地址），必须转换为公网地址。

| NAT类型 | 说明 | 映射关系 | 适用场景 |
|---------|------|---------|---------|
| 静态NAT | 一个私网IP固定映射一个公网IP | 1:1 | 服务器对外发布 |
| 动态NAT | 从公网IP池中动态分配 | N:N (池中取) | 多对多，但公网IP数有限 |
| NAPT/PAT | 多个私网IP共享一个公网IP，通过端口号区分 | N:1 | 最常用，企业出口 |

**NAPT示例：**
```
内网设备A (192.168.1.10:1234) → NAT设备 → 公网 (202.1.1.1:50001)
内网设备B (192.168.1.20:1234) → NAT设备 → 公网 (202.1.1.1:50002)
```
靠端口号区分不同内网设备的会话。

## 十、数据转发流程

### Q1: 同网段通信全过程

**A:**

**场景：** PC-A (192.168.1.10) → PC-B (192.168.1.20)，同一网段，中间经过交换机。

**完整流程：**
1. PC-A判断目的IP与自己同网段（AND掩码后网络地址相同）
2. PC-A查ARP缓存表有没有192.168.1.20的MAC
3. 如果没有：发送ARP Request（广播）问"192.168.1.20的MAC是多少？"
4. 交换机泛洪该ARP广播帧
5. PC-B收到后回复ARP Reply（单播），告知自己的MAC
6. PC-A学到B的MAC，写入ARP缓存
7. PC-A封装帧：源MAC=A的MAC，目的MAC=B的MAC，源IP=A，目的IP=B
8. 交换机查MAC表，从B所在端口转发
9. PC-B收到帧，解封装，完成通信

**关键：** 同网段通信不经过路由器，直接二层转发。

---

### Q2: 跨网段通信全过程

**A:**

**场景：** PC-A (192.168.1.10/24, 网关.1) → Server (10.1.1.100/24)，不同网段。

**完整流程：**
1. PC-A判断目的IP与自己不在同一网段 → 需要发给网关
2. PC-A查ARP缓存中网关(192.168.1.1)的MAC，没有则ARP广播请求
3. 获得网关MAC后，封装帧：
   - 源MAC=A，目的MAC=网关，源IP=A(192.168.1.10)，目的IP=Server(10.1.1.100)
4. 帧到达路由器（网关），路由器解封装去帧头，查看目的IP
5. 路由器查路由表，找到10.1.1.0/24的出接口和下一跳
6. 路由器ARP解析下一跳（或目的Server）的MAC
7. 路由器重新封装帧：源MAC=路由器出接口MAC，目的MAC=下一跳/Server MAC
8. IP头TTL减1
9. 从出接口转发...（如果还有多跳，继续重复5-8）
10. 最终到达Server，解封装完成通信

---

### Q3: 在跨网段通信中，源/目的 MAC 和源/目的 IP 分别会怎么变化？

**A:**

| 位置 | 源MAC | 目的MAC | 源IP | 目的IP |
|------|-------|---------|------|--------|
| PC-A发出 | A的MAC | 网关MAC | 192.168.1.10 | 10.1.1.100 |
| 路由器1转发 | 路由器1出口MAC | 路由器2入口MAC | 192.168.1.10 | 10.1.1.100 |
| 路由器2转发 | 路由器2出口MAC | Server MAC | 192.168.1.10 | 10.1.1.100 |
| Server收到 | — | — | 192.168.1.10 | 10.1.1.100 |

**核心规律：**
- **源/目的IP：端到端不变**（除非经过NAT）
- **源/目的MAC：每跳改变**（每经过一个路由器就替换为当前跳的MAC）
- IP负责全程导航，MAC负责每段接力

## 十一、OSPF

### Q1: OSPF 的基本概念

**A:**

**OSPF（Open Shortest Path First，开放最短路径优先）：** 基于链路状态的IGP（内部网关协议），用于自治系统（AS）内部的路由计算。

| 概念 | 说明 |
|------|------|
| 链路状态协议 | 每台路由器收集全网拓扑信息（LSDB），独立用SPF算法计算最短路径 |
| 区域 (Area) | 将大型网络划分为多个区域，减少LSA泛洪范围和SPF计算量 |
| Area 0 (骨干区域) | 所有非骨干区域必须与Area 0相连，区域间路由经Area 0传递 |
| Router-ID | 路由器在OSPF域中的唯一标识（32bit，格式如IP地址） |
| 邻居 (Neighbor) | 建立了双向Hello关系的路由器 |
| 邻接 (Adjacency) | 完成了LSDB同步的邻居（Full状态） |
| DR/BDR | 广播网络中选举的指定路由器/备份指定路由器，减少邻接关系数量 |

**Router-ID选举规则：**
1. 手动配置的Router-ID（优先）
2. Loopback接口最大IP
3. 物理接口最大IP

---

### Q2: OSPF 五种报文

**A:**

| 报文类型 | 名称 | 作用 |
|---------|------|------|
| Type 1 | Hello | 发现和维护邻居关系，选举DR/BDR |
| Type 2 | DBD (Database Description) | 描述本地LSDB的摘要信息 |
| Type 3 | LSR (Link-State Request) | 请求对方发送自己缺少的LSA |
| Type 4 | LSU (Link-State Update) | 携带具体的LSA内容发给对方 |
| Type 5 | LSAck (Link-State Ack) | 确认收到的LSA |

**关键考点：**
- Hello报文周期发送（广播网10s，P2P/NBMA 30s），Dead时间默认为Hello的4倍
- Hello中携带的参数必须一致才能建立邻居：Hello/Dead间隔、区域ID、认证、网络类型等

---

### Q3: OSPF 邻接建立的状态机

**A:**

```
Down → Init → 2-Way → ExStart → Exchange → Loading → Full
```

| 状态 | 说明 |
|------|------|
| **Down** | 初始状态，未收到对方Hello |
| **Init** | 收到Hello，但Hello中不包含自己的Router-ID |
| **2-Way** | 收到的Hello中包含自己的Router-ID → 双向通信确认 |
| **ExStart** | 协商主从关系（Router-ID大的为Master），确定DD序列号 |
| **Exchange** | 交换DBD报文，互相描述自己LSDB的摘要 |
| **Loading** | 根据DBD发现差异，发LSR请求缺少的LSA，收LSU获取完整LSA |
| **Full** | LSDB同步完成，邻接关系建立 |

**关键考点：**
- 广播网络中，非DR/BDR之间停在2-Way（不建邻接，减少邻接数量）
- P2P网络中，所有邻居都建Full邻接
- DR/BDR选举在2-Way阶段完成

---

### Q4: 多区域设计的原因

**A:**

**为什么要划分区域：**
1. **减少LSA泛洪范围**：LSA只在区域内泛洪，跨区域传递摘要
2. **缩小LSDB规模**：每台路由器只需存储所在区域的完整拓扑
3. **减轻SPF计算负担**：区域内拓扑变化不影响其他区域
4. **加快收敛速度**：影响范围缩小，收敛更快

**OSPF 区域类型：**

| 区域类型 | 允许的LSA | 特点 |
|----------|----------|------|
| 普通区域 | 1, 2, 3, 4, 5 | 无限制 |
| Stub区域 | 1, 2, 3 | 不接收4/5类LSA，ABR注入默认路由 |
| Totally Stub | 1, 2 | 不接收3/4/5类LSA，ABR注入默认路由 |
| NSSA | 1, 2, 3, 7 | 允许本地引入外部路由(7类LSA) |

**OSPF LSA 类型：**

| LSA类型 | 名称 | 产生者 | 泛洪范围 |
|---------|------|--------|----------|
| Type 1 | Router LSA | 每台路由器 | 区域内 |
| Type 2 | Network LSA | DR | 区域内 |
| Type 3 | Summary LSA | ABR | 区域间 |
| Type 4 | ASBR Summary LSA | ABR | 区域间 |
| Type 5 | AS External LSA | ASBR | 整个AS |
| Type 7 | NSSA External LSA | NSSA的ASBR | NSSA区域内 |

---

## 十二、BGP 基础

### Q1: BGP 和 IGP 的区别

**A:**

| 对比项 | BGP (EGP) | OSPF/IS-IS (IGP) |
|--------|-----------|-------------------|
| 应用范围 | AS之间（也可AS内部IBGP） | AS内部 |
| 协议类型 | 路径矢量协议 | 链路状态协议 |
| 传输方式 | TCP 端口179 | IP直接封装（OSPF协议号89） |
| 路由选择依据 | 基于属性和策略（丰富的选路规则） | 基于度量值（Cost） |
| 扩展性 | 支撑互联网规模（全球路由表80万+条） | 适合中大型企业网 |
| 收敛速度 | 较慢（分钟级，策略驱动） | 较快（秒级） |
| 路由携带信息 | AS-Path、Next-Hop、MED、Local-Pref等属性 | 仅Cost |
| 设计目标 | 策略控制、环路避免（AS-Path） | 最优路径计算 |

**为什么说BGP是"路径矢量"协议：**
- BGP路由携带完整的AS路径（AS-Path属性）
- 通过检查AS-Path是否包含自己的AS号来防环
- 不像链路状态协议那样需要全网拓扑信息

---

### Q2: IBGP vs EBGP

**A:**

| 对比项 | IBGP | EBGP |
|--------|------|------|
| 定义 | 同一AS内部的BGP邻居 | 不同AS之间的BGP邻居 |
| 默认TTL | 255（可以建Loopback邻居） | 1（必须直连，或改TTL） |
| AS-Path修改 | 不修改（不添加本AS号） | 添加本AS号到AS-Path |
| Next-Hop行为 | 默认不改变Next-Hop（需设next-hop-local） | 改为自己接口IP |
| 水平分割 | 有（IBGP学的路由不传给其他IBGP邻居） | 无 |
| 防环机制 | 需全互联/路由反射器/联盟 | AS-Path环路检测 |

**IBGP水平分割问题的解决方案：**
- **全互联 (Full Mesh)**：N台设备需要 N×(N-1)/2 个邻居关系，不可扩展
- **路由反射器 (Route Reflector)**：RR反射IBGP路由给客户端，减少邻居数
- **联盟 (Confederation)**：AS内再划分sub-AS，sub-AS间用EBGP规则

---

### Q3: BGP 建邻的基本条件

**A:**

1. **TCP可达**：两端能建立TCP连接（端口179）——需路由可达
2. **AS号配置正确**：本端的remote-as必须与对端的local-as一致
3. **Router-ID不冲突**：两端Router-ID不同
4. **认证一致**：如果配置了认证，两端密码必须相同
5. **EBGP直连或修改TTL**：EBGP默认TTL=1，非直连需要 `ebgp-max-hop`
6. **IBGP建邻用Loopback**（推荐）：提高邻居稳定性（Loopback不会因单链路故障而下线）

---

### Q4: BGP 的路由选路原则（简要）

**A:**

BGP选路原则（从高到低优先级）：

| 优先级 | 属性 | 规则 |
|--------|------|------|
| 1 | Local_Preference | 值越大越优（本AS内使用） |
| 2 | 本地始发 | network/aggregate发出的优先 |
| 3 | AS_Path | 路径越短越优 |
| 4 | Origin | IGP > EGP > Incomplete |
| 5 | MED | 值越小越优（仅比较来自同一AS的） |
| 6 | EBGP > IBGP | 外部路由优于内部路由 |
| 7 | IGP Metric | 到Next-Hop的IGP度量越小越优 |
| 8 | Router-ID | 越小越优（最终打破平局） |

**关键考点：**
- Local_Pref：出方向策略，"我从哪收的路由更好"
- AS-Path：越短说明经过AS越少，越近
- MED：入方向策略，"你从我哪个出口进来更好"

---

## 十三、ACL

### Q1: 基本 ACL vs 高级 ACL

**A:**

| 对比项 | 基本ACL | 高级ACL |
|--------|---------|---------|
| 编号范围 | 2000-2999 | 3000-3999 |
| 匹配条件 | 仅源IP地址 | 源IP、目的IP、协议号、源/目的端口 |
| 颗粒度 | 粗（只能基于谁发的来过滤） | 细（可精确到具体应用/端口） |
| 部署位置建议 | 靠近目的端（因为只匹配源，放源头会误杀其他流量） | 靠近源端（匹配精确，尽早过滤节省带宽） |

---

### Q2: ACL 匹配逻辑

**A:**

**匹配规则：**
1. **从上到下**逐条匹配（按rule编号从小到大）
2. **一旦命中**则执行对应动作（permit/deny），不再继续匹配
3. 所有规则都不匹配 → 执行**隐式拒绝**（默认deny all）

**通配符掩码（Wildcard Mask）：**
- 与子网掩码相反：0表示必须匹配，1表示忽略
- 例：0.0.0.255 = 匹配前24位，忽略后8位（即一个/24网段）
- 例：0.0.0.0 = 精确匹配这一个地址

---

### Q3: ACL 的典型应用场景

**A:**

| 场景 | 用法 |
|------|------|
| 包过滤 | 接口上应用ACL，控制流量进出（permit/deny） |
| NAT | ACL定义哪些私网地址允许做NAT转换 |
| 路由过滤 | 在路由策略中引用ACL，控制路由的发布和接收 |
| VPN感兴趣流 | ACL定义哪些流量需要走VPN隧道加密 |
| QoS分类 | ACL匹配特定流量进行标记和队列调度 |
| 登录控制 | 限制哪些IP可以Telnet/SSH到设备 |

---

## 十四、网络可靠性

### Q1: 链路聚合（Eth-Trunk）的作用和模式

**A:**

**链路聚合**：将多条物理链路捆绑成一条逻辑链路，实现带宽叠加和冗余备份。

| 模式 | 说明 | 特点 |
|------|------|------|
| 手工模式 | 管理员指定哪些成员链路活跃 | 简单，不运行协议 |
| LACP模式 | 通过LACP协议协商活跃链路 | 可检测链路故障，自动切换，更可靠 |

**LACP 优势：**
- 自动协商，检测成员链路的连通性
- 支持活跃/备份链路：配置最大活跃数，超出的为备份
- 一端故障时自动将备份链路激活

**负载分担算法：**
- 基于源MAC / 目的MAC / 源IP / 目的IP / 源目的IP等Hash
- 不同算法适合不同场景（多对一用源IP Hash效果好）

---

### Q2: VRRP 解决什么问题、基本原理

**A:**

**问题：** 终端设备通常只配一个默认网关。如果网关路由器故障，所有终端断网。

**VRRP（Virtual Router Redundancy Protocol）解决方案：**
- 多台路由器虚拟成一台，共享一个虚拟IP（VIP）和虚拟MAC
- 终端的网关指向VIP
- 一台为Master负责转发，其余为Backup待命
- Master故障时Backup自动接管VIP，终端无感知

**选举规则：**
1. 优先级高者为Master（默认100，范围0-255）
2. 优先级相同比接口IP地址，大者优先
3. 支持抢占模式（高优先级路由器恢复后抢回Master）

**VRRP虚拟MAC格式：** 00-00-5E-00-01-{VRID}

---

### Q3: BFD 的作用

**A:**

**BFD（Bidirectional Forwarding Detection，双向转发检测）：** 独立于路由协议的毫秒级故障检测机制。

**为什么需要BFD：**
- OSPF Hello默认10s，Dead 40s → 故障检测太慢
- BGP Keepalive默认60s，Hold 180s → 更慢
- BFD检测间隔可达毫秒级（如3×10ms=30ms检测到故障）

**工作方式：**
- 在两端建立BFD会话，周期互发检测报文
- 连续N次没收到回复 → 判定链路故障
- 通知联动的上层协议（OSPF/BGP/静态路由）立即收敛

**BFD联动典型场景：**
- BFD + OSPF：BFD检测到邻居不可达，立即触发OSPF重新计算路由
- BFD + 静态路由：BFD检测到下一跳不可达，该静态路由失效，切换到备份路由

---

## 十五、堆叠与集群

### Q1: 堆叠（iStack/CSS）的概念和目的

**A:**

**堆叠**：将多台物理交换机通过专用堆叠线缆/端口连接，在逻辑上虚拟成一台设备统一管理和转发。

| 术语 | 说明 |
|------|------|
| iStack | 华为盒式交换机堆叠 |
| CSS (Cluster Switch System) | 华为框式交换机集群 |
| VSS | Cisco的堆叠方案 |

**目的/优势：**
1. **简化管理**：多台设备当一台管理，一个IP/一套配置
2. **跨设备链路聚合**：下游设备可以把链路分到不同堆叠成员，消除STP阻塞
3. **提升可靠性**：一台成员故障，其他成员继续工作
4. **扩展性能**：聚合多台设备的转发能力

---

### Q2: 主备选举机制

**A:**

堆叠中的角色：
- **Master（主）**：负责整个堆叠系统的管理和决策
- **Standby（备）**：Master故障时接管
- **Slave（从）**：仅做转发，不参与管理决策

**选举规则（依次比较）：**
1. 当前已是Master的优先（运行时不抢占）
2. 堆叠优先级高的
3. MAC地址小的

---

### Q3: 堆叠分裂（脑裂）和 MAD 检测

**A:**

**堆叠分裂**：堆叠线缆断裂导致一个堆叠系统变成两个独立系统，双方都认为自己是Master → 两套相同配置（IP冲突、MAC冲突）→ 网络混乱。

**MAD（Multi-Active Detection，多主检测）：** 检测堆叠分裂后，让其中一方主动关闭业务端口，避免冲突。

**MAD检测方式：**

| 方式 | 原理 |
|------|------|
| 直连检测 (LACP MAD) | 通过下联设备的Eth-Trunk发现多个管理MAC → 判断分裂 |
| 代理检测 | 通过第三方设备（如另一台交换机）代理检测 |

**分裂后处理：** 检测到多主后，优先级低/后启动的一方关闭所有业务端口（仅保留管理口），等待修复堆叠线缆后恢复。

---

## 十六、M-LAG

### Q1: M-LAG 解决什么问题？与堆叠的定位差异？

**A:**

**M-LAG（Multichassis Link Aggregation Group，跨设备链路聚合）：** 两台物理独立的设备对外表现为一个链路聚合系统，下游设备将上行链路分到两台设备实现冗余。

**M-LAG vs 堆叠的定位差异：**

| 对比项 | 堆叠 | M-LAG |
|--------|------|-------|
| 管理面 | 合一（一台逻辑设备） | 独立（两台独立设备各自管理） |
| 控制面 | 合一 | 独立（各自运行路由协议） |
| 升级方式 | 整体升级（影响大） | 可逐台升级（影响小） |
| 故障域 | 大（软件Bug可能两台一起挂） | 小（独立系统互不影响） |
| 连接方式 | 专用堆叠线缆 | 普通以太网链路 (Peer-link) |
| 扩展性 | 2-N台 | 固定2台 |
| 适用场景 | 接入/汇聚层简化管理 | 核心/汇聚层高可靠、独立升级 |

---

### Q2: M-LAG 的基本架构

**A:**

```
        ┌─────────────┐         ┌─────────────┐
        │  Device A   │◄═══════►│  Device B   │  ← Peer-link（数据+协商）
        │  (M-LAG 主) │  ┆┆┆┆   │  (M-LAG 备) │
        └──────┬──────┘         └──────┬──────┘
               │ Keepalive (心跳)       │
               └────────────────────────┘
                      │         │
                      └────┬────┘  ← M-LAG接口（跨设备Eth-Trunk）
                           │
                    ┌──────┴──────┐
                    │  下游设备    │
                    └─────────────┘
```

| 组件 | 作用 |
|------|------|
| **Peer-link** | 两台M-LAG设备之间的互联链路，传输数据流量+MAC/ARP等信息同步 |
| **Keepalive链路** | 心跳检测通道（独立管理网络），判断对端是否存活 |
| **DFS Group** | M-LAG的逻辑组，绑定Peer-link和Keepalive配置 |
| **M-LAG接口** | 跨两台设备的逻辑Eth-Trunk，下游设备看到的是一个聚合组 |

---

### Q3: Peer-link 断了会发生什么？

**A:**

1. Peer-link断裂后，两台设备无法同步数据和MAC表
2. Keepalive链路仍通 → 检测到Peer-link断但对端还活着
3. **备设备**（Secondary）关闭所有M-LAG接口 → 流量全走主设备
4. 这样避免流量黑洞和MAC表不一致

**如果Peer-link和Keepalive都断了：**
- 双方都认为对端宕机 → 双主（脑裂）
- 两台都保持M-LAG接口UP → 可能引起MAC冲突
- 所以Keepalive必须走独立链路（带外管理网），避免和Peer-link同时断

---

### Q4: M-LAG 场景下流量转发路径

**A:**

**正常情况（已知单播）：**
- 下游设备基于Hash将流量分到两台M-LAG设备
- 每台设备本地转发（有本地出口就不走Peer-link）
- Peer-link只在本地没有目的出口时才转发数据

**一台M-LAG设备故障时：**
- 下游Eth-Trunk感知成员链路Down，LACP将流量切到存活设备
- 切换时间秒级（LACP超时）
- 不影响三层路由收敛（两台设备的路由独立）

---

## 十七、VXLAN

### Q1: VXLAN 解决什么问题？

**A:**

**VXLAN（Virtual Extensible LAN，虚拟可扩展局域网）：** 一种Overlay网络虚拟化技术，通过MAC-in-UDP封装实现跨三层网络的大二层域。

**传统VLAN的局限和VXLAN的解决：**

| 问题 | 传统VLAN的局限 | VXLAN怎么解决 |
|------|---------------|--------------|
| 数量限制 | VLAN ID 12bit，最多4094个 | VNI 24bit，支持约1600万个 |
| 二层扩展受限 | STP阻塞冗余链路，二层域不能太大 | L2 over L3，底层用ECMP多路径转发 |
| VM迁移 | 传统网络二层域受物理限制，VM不能跨三层迁移 | 大二层隧道跨越三层网络 |
| 带宽浪费 | STP阻塞链路不转发流量 | Underlay用三层ECMP，所有链路都利用 |

---

### Q2: VXLAN 的封装格式

**A:**

```
┌──────────────────────────────────────────────────────────────┐
│ 外层以太网头(14B) │ 外层IP头(20B) │ UDP头(8B) │ VXLAN头(8B) │ 原始L2帧 │
└──────────────────────────────────────────────────────────────┘
```

| 层次 | 内容 | 说明 |
|------|------|------|
| 外层以太网头 | 外层源/目的MAC | 下一跳设备的MAC（逐跳变化） |
| 外层IP头 | 源VTEP IP / 目的VTEP IP | 隧道两端的IP地址（Underlay可路由） |
| UDP头 | 源端口(Hash) / 目的端口(4789) | 源端口基于内层报文Hash，用于ECMP负载均衡 |
| VXLAN头 | VNI (24bit) + 标志位 | 标识属于哪个VXLAN网络 |
| 原始L2帧 | 内层完整以太网帧 | 租户的原始流量，带内层MAC/IP |

**关键考点：**
- 封装增加50字节开销（14+20+8+8）→ 需注意MTU问题（Underlay MTU建议≥1600）
- UDP源端口Hash计算保证同一流走同一路径，不同流走不同路径（ECMP负载均衡）
- 目的端口固定4789（IANA分配）

---

### Q3: VNI 与 VLAN 的映射关系

**A:**

| 概念 | 说明 |
|------|------|
| VNI (VXLAN Network Identifier) | 24bit，标识一个VXLAN逻辑网段 |
| BD (Bridge Domain) | 华为设备中的广播域概念，与VNI一一映射 |
| VLAN | 本地接入侧的VLAN标签 |

**映射关系：**
```
终端流量(VLAN 10) → 交换机接入 → 映射到BD 10 → BD 10绑定VNI 5010 → VXLAN封装发送
```

- 不同站点可以用不同的本地VLAN映射到同一VNI → 实现跨站点二层互通
- 一个VNI = 一个逻辑二层广播域

---

### Q4: VTEP 的概念

**A:**

**VTEP（VXLAN Tunnel Endpoint，VXLAN隧道端点）：** 执行VXLAN封装和解封装的网络设备（通常是Leaf交换机或虚拟交换机）。

**VTEP的职责：**
- 对进入的租户流量执行VXLAN封装（加外层头）
- 对收到的VXLAN报文执行解封装（去外层头恢复原始帧）
- 维护本地MAC表和远端MAC-VTEP映射

**NVE接口：** 华为设备中VTEP的逻辑接口，配置源IP（即VTEP IP，通常用Loopback）

---

### Q5: BUM 流量处理（头端复制 vs 组播）

**A:**

**BUM流量**：Broadcast（广播）、Unknown unicast（未知单播）、Multicast（组播）——这些帧需要泛洪。

在VXLAN中泛洪方式：

| 方式 | 原理 | 优缺点 |
|------|------|--------|
| 头端复制 (Ingress Replication) | 入口VTEP将BUM帧复制N份，分别单播封装发给所有远端VTEP | 简单，不需要组播支持；但VTEP多时复制量大 |
| 组播 | 入口VTEP将BUM帧封装成组播报文，Underlay网络组播转发 | 效率高；但需要Underlay支持组播路由，配置复杂 |
| EVPN控制平面 | 通过BGP EVPN Type-3路由建立复制列表 | 主流方案，无需组播也可实现 |

**主流方案：** EVPN + 头端复制。EVPN自动建立VTEP列表，BUM帧按列表复制发送。

---

## 十八、网络管理协议

### Q1: SNMP 的作用和版本差异

**A:**

**SNMP（Simple Network Management Protocol，简单网络管理协议）：** 用于网络设备的监控和管理。

**架构：**
- NMS（Manager）：网管站，发起查询和接收告警
- Agent：设备上的代理程序，响应查询和发送Trap
- MIB：管理信息库，定义可管理对象的数据结构

**版本对比：**

| 对比项 | SNMPv1 | SNMPv2c | SNMPv3 |
|--------|--------|---------|--------|
| 安全机制 | 社区名（明文） | 社区名（明文） | 用户认证+加密（USM） |
| 认证 | 无 | 无 | MD5/SHA |
| 加密 | 无 | 无 | DES/AES |
| GetBulk | 不支持 | 支持 | 支持 |
| 安全级别 | 低 | 低 | 高 |
| 实际使用 | 淘汰中 | 仍广泛使用 | 安全要求高的场景 |

---

### Q2: Syslog 分级

**A:**

**Syslog**：设备将日志信息发送到日志服务器集中管理。

| 级别 | 编号 | 名称 | 说明 |
|------|------|------|------|
| 0 | Emergency | 系统不可用 |
| 1 | Alert | 必须立即处理 |
| 2 | Critical | 严重错误 |
| 3 | Error | 错误 |
| 4 | Warning | 警告 |
| 5 | Notice | 正常但重要 |
| 6 | Informational | 一般信息 |
| 7 | Debug | 调试信息 |

**关键考点：** 数字越小级别越高（越严重）。生产环境通常记录到级别5或6，Debug信息量太大一般排错时才开启。

---

### Q3: NETCONF / YANG 的基本概念

**A:**

**NETCONF：** 基于XML的网络配置管理协议，通过SSH承载（端口830）。

**相比传统CLI的优势：**
- 支持事务性操作（commit/rollback）——要么全部成功，要么回滚
- 支持配置锁定（lock/unlock）——防止多人同时修改冲突
- 结构化数据（XML）——易于程序解析和自动化
- 区分候选配置和运行配置——修改候选配置确认无误后再提交

**YANG：** 数据建模语言，定义网络设备的配置和状态数据模型。NETCONF用YANG模型来描述"设备有哪些可配置项、什么格式"。

**NETCONF 四层模型：**
```
┌─────────────────┐
│   Content       │  ← 配置/状态数据 (YANG模型定义)
├─────────────────┤
│   Operations    │  ← get, get-config, edit-config, lock, unlock, commit
├─────────────────┤
│   Messages      │  ← RPC, RPC-reply, Notification
├─────────────────┤
│   Transport     │  ← SSH (端口830)
└─────────────────┘
```

---

### Q4: Telemetry 和传统 SNMP 轮询的区别

**A:**

| 对比项 | SNMP 轮询 (Pull) | Telemetry 推送 (Push) |
|--------|------------------|----------------------|
| 数据获取方式 | NMS主动轮询设备 | 设备主动推送给采集器 |
| 实时性 | 秒级-分钟级（取决于轮询间隔） | 亚秒级（可配100ms级推送） |
| 设备CPU影响 | 大（频繁轮询消耗CPU） | 小（订阅后按需触发推送） |
| 数据格式 | MIB/ASN.1（复杂） | YANG + GPB/JSON（结构化、易解析） |
| 扩展性 | 差（设备多时NMS成瓶颈） | 好（分布式采集器） |
| 适用场景 | 传统网管、小规模监控 | 大规模自动化运维、AI分析、实时监控 |

**Telemetry 核心优势：** 实时性强 + 设备主动推送 + 大规模适用。是现代网络运维（尤其数据中心）的发展方向。

---

## 十九、路由控制与策略

### Q1: 路由优先级 vs 路由开销

**A:**

| 概念 | 作用 | 比较范围 | 值的含义 |
|------|------|---------|---------|
| 路由优先级 (Preference) | 不同路由来源之间选优 | 跨协议比较 | 值越小越优先 |
| 路由开销 (Metric/Cost) | 同一路由协议内部选优 | 同协议内比较 | 值越小越优先 |

**华为设备默认路由优先级：**

| 路由来源 | 优先级 (Preference) |
|---------|-------------------|
| Direct（直连） | 0 |
| OSPF Internal | 10 |
| Static（静态） | 60 |
| RIP | 100 |
| OSPF External | 150 |
| BGP | 255 |

**选路顺序：**
1. 先最长前缀匹配
2. 同前缀再比优先级（不同协议间）
3. 同协议再比开销（同协议内不同路径）

---

### Q2: 路由引入（import/redistribution）的概念

**A:**

**路由引入**：将一种路由协议学到的路由注入到另一种路由协议中。

**为什么需要：**
- 网络中可能同时运行多种路由协议（如核心OSPF，边界BGP）
- 不同协议之间的路由信息默认不互通
- 需要引入机制让各协议的路由能跨域传递

**常见场景：**
- OSPF引入静态路由（发布默认路由到OSPF域）
- BGP引入OSPF路由（将内部路由通告给外部AS）
- OSPF引入直连路由

**关键考点：**
- 引入时需要指定Cost/Metric，否则可能导致选路异常
- 不加路由策略过滤就引入 → 可能引入不需要的路由，造成路由环路或黑洞

### Q3: 路由过滤的基本方法

**A:**

| 工具 | 用途 | 特点 |
|------|------|------|
| ACL | 匹配路由的网络地址 | 只能匹配地址，不能匹配掩码长度 |
| IP Prefix-List | 匹配路由前缀和掩码长度 | 可精确控制"哪个网段/多长掩码"，比ACL灵活 |
| Route-Policy | 综合路由策略工具 | 可匹配多种条件 + 执行动作（修改属性） |
| Filter-Policy | 路由过滤策略 | 对路由协议收到/发布的路由进行过滤 |

**Route-Policy 结构：**
```
route-policy RP1 permit node 10
  if-match ip-prefix PL1        ← 匹配条件
  apply cost 100                ← 执行动作（修改Cost）
route-policy RP1 deny node 20   ← 不匹配的拒绝
```

**IP Prefix-List 示例：**
```
ip ip-prefix PL1 permit 10.0.0.0/8 less-equal 24
```
含义：匹配以10开头、掩码长度在/8到/24之间的所有路由。
