| 依赖项 | 最低版本 | 说明 |

### 1.2 网络依赖

| 场景 | 依赖 | 说明 |
|------|------|------|

| 离线模式 | 无网络依赖 | 通过浏览器上传 .ampkg 包 |

### 1.3 权限依赖

| 操作 | 最低权限 |
|------|----------|
| 查看版本信息 | SiteAdmin / Viewer |
| 执行升级/降级/卸载 | SuperAdmin |
| 上传离线包 | SuperAdmin |

### 1.4 业务前置条件

| 条件 | 说明 |
|------|------|
| 建议在业务低峰期操作 | 升级/降级过程中对应 App 服务短暂中断 ~30s |

| 建议确认无 Critical 告警 | 避免升级过程中叠加故障 |
| HA 环境主备节点均在线 | 滚动升级要求双节点可用 |

## 2. 功能需求

### 2.1 平台底座升级

#### 2.1.1 功能说明

管理 AmpCon OS 底座的版本升级。底座直接安装在物理服务器或虚拟机上，是所有 App 运行的基础环境。

依赖关系：**App 依赖底座，底座不依赖 App**（类似手机 App 要求最低 OS 版本）。每个 App 声明自己所需的最低底座版本，底座本身不关心上面运行什么 App。

因此底座升级没有任何 App 相关的前置条件，随时可以执行（仅需基础检查：磁盘空间、HA 状态）。高版本底座天然兼容已安装的旧版 App。

底座升级支持在线和离线两种方式（与 App 共用同一套在线/离线机制），升级前自动创建快照用于降级恢复。

#### 2.1.2 竞品功能设计及流程说明

| 竞品 | 实现方式 |
|------|----------|
| UniFi (Ubiquiti) | 底座(UniFi OS)与 App(Network/Protect/Talk/Access)独立升级，架构最接近 AmpCon。底座直接安装在 Dream Machine 硬件或 VM 上，App 在底座之上独立安装和升级 |
| Cisco DNA Center | 底座与 App 捆绑为整体镜像升级，不支持独立 App 升级 |
| Aruba Central | 纯 SaaS 云架构，自动推送升级，无离线能力，无底座概念 |

AmpCon 与 UniFi 类似采用底座+App 分离架构，差异点：AmpCon 支持离线升级、版本依赖校验、App 降级和精细卸载。

#### 2.1.3 功能业务流程

```
用户进入 App Center
    │
    ▼
系统检测网络状态（在线/离线）
    │
    ▼
展示底座当前版本 vs 最新版本（在线获取或离线上传）
    │
    ├─ 无更新 → 显示 "Current"
    │
    └─ 有更新 → 显示 "Upgrade OS"
         │
         ▼
    用户点击 "Upgrade OS"
         │
         ▼
    系统执行前置校验（磁盘空间、HA 状态）
    注意：无需检查 App 版本，底座升级无 App 前置条件
         │
         ▼
    创建快照 → 执行底座升级
         │
         ├─ 成功 → 刷新版本信息
         │
         └─ 失败 → 自动从快照恢复
```

> **设计说明**：底座升级不检查 App 版本。依赖关系是单向的——App 依赖底座，底座不依赖 App。高版本底座天然兼容旧版 App 的 API 调用。

底座卡片位于 App 列表上方，独立展示：

#### 2.1.8 异常与容错处理

| 异常场景 | 处理方式 |
|----------|----------|
| 升级过程中断电 | 重启后自动检测未完成的升级，从快照恢复 |
| 升级包校验失败 | 拒绝安装，提示 "Package signature verification failed" |
| 升级后服务启动失败 | 自动触发快照恢复，回退到升级前版本 |
| HA 环境 Standby 升级失败 | 停止滚动升级，Primary 保持不变，告警通知 |
| 网络中断（在线升级中） | 下载中断，提示重试或切换离线模式 |

#### 2.1.9 权限控制要求

| 操作 | 权限 |

| 查看底座版本信息 | SiteAdmin / Viewer |
| 查看 Release Notes | SiteAdmin / Viewer |
| 执行底座升级 | SuperAdmin |
| 上传底座离线包 | SuperAdmin |

#### 2.1.10 功能约束与边界

| 约束 | 说明 |
|------|------|
| 底座升级无 App 前置条件 | 底座不依赖 App，随时可升级（仅需磁盘空间和 HA 基础检查） |
| 高版本底座兼容旧 App | 底座 API 向后兼容，已安装的旧版 App 在新底座上继续正常运行 |
| 同一时间只能执行一个底座升级操作 | 并发锁 |
| HA 环境采用滚动升级 | 先 Standby → 切换 → 再原 Primary |
| 快照仅保留一份 | 新升级覆盖旧快照 |
| 底座降级需检查 App 兼容性 | 若已安装 App 要求的最低底座版本高于降级目标版本，这些 App 降级后可能无法运行，需警告用户 |
| 底座在线/离线升级共用同一机制 | 在线从云端下载，离线从上传的 .ampkg 包安装 |

#### 2.1.11 非功能需求

| 项目 | 指标 |
|------|------|
| 升级耗时 | ≤ 5 分钟（不含下载时间） |
| 服务中断时间 | ≤ 60 秒（HA 环境零中断） |
| 快照创建时间 | ≤ 30 秒 |
| 快照恢复时间 | ≤ 120 秒 |
| 最大包体积 | 2 GB |

### 2.2 App 在线升级

#### 2.2.1 功能说明

在控制器可访问外网的环境下，从云端软件仓库获取 App 最新版本信息，支持一键升级或逐版本升级。每个 App 可展开查看完整版本历史和 Release Notes，支持升级到最新版或任意中间版本。

#### 2.2.2 竞品功能设计及流程说明

| 竞品 | 实现方式 |
|------|----------|
| Cisco DNA Center | 仅支持升级到最新版，不支持选择中间版本 |
| Aruba Central | 云端自动推送，管理员确认后执行 |
| Juniper Mist | 支持指定版本升级，但无 Release Notes 内联展示 |

AmpCon 差异点：支持逐版本升级（选择任意中间版本），Release Notes 内联展示，每个版本独立升级按钮。

#### 2.2.3 功能业务流程

```
系统检测到在线状态
    │
    ▼
从云端拉取各 App 最新版本 + Release Notes
    │
    ▼
对比当前安装版本，标记有更新的 App
    │
    ▼
用户选择操作：
    ├─ "Upgrade All" → 批量升级所有有更新的 App（升级到各自最新版）
    │
    └─ 展开某个 App → 查看版本历史
         │
         ├─ 点击 "Upgrade to vX.X.X"（最新版）
         │
         └─ 点击 "Upgrade to vX.X.X"（中间版本）
              │
              ▼
         前置校验 → 创建快照 → 下载包 → 执行升级 → DB 迁移 → 服务重启
              │
              ├─ 成功 → 刷新版本，Installed 标签移至新版本
              └─ 失败 → 自动快照恢复
```

#### 2.2.8 异常与容错处理

| 异常场景 | 处理方式 |

#### 2.2.10 功能约束与边界

| 约束 | 说明 |
|------|------|
| 同一时间只能执行一个升级操作 | 并发锁，队列等待 |
| 新版 App 可能要求更高底座版本 | 升级前校验，不满足则阻止 |
| 升级不可跳过 DB 迁移 | 每个版本的迁移脚本必须按序执行 |
| 跳版本升级时自动链式执行中间迁移 | 如 v2.4→v2.6 会依次执行 v2.5、v2.6 的迁移脚本 |

#### 2.2.11 非功能需求

| 项目 | 指标 |
|------|------|
| 版本检查响应时间 | ≤ 3 秒 |
| 单 App 升级耗时 | ≤ 3 分钟（不含下载） |
| 服务中断时间 | ≤ 30 秒 |
| 并发下载带宽 | 不超过 100 Mbps |

### 2.3 App 离线升级

#### 2.3.1 功能说明

在控制器无法访问外网的隔离环境下，通过浏览器上传 .ampkg 离线升级包完成 App 升级。上传后包进入"暂存"状态，用户确认后执行安装。离线升级完成后，版本信息自动更新。

#### 2.3.2 竞品功能设计及流程说明

| 竞品 | 实现方式 |
|------|----------|
| Cisco DNA Center | 支持离线包上传，但需手动指定目标 App |
| Aruba Central | 不支持离线升级（纯云架构） |
| H3C CloudNet | 支持 .bin 包上传，无暂存确认机制 |

AmpCon 差异点：上传后自动解析包元数据（App 类型、版本），暂存确认后再执行，支持同时暂存多个包。

#### 2.3.3 功能业务流程

```
管理员在有网环境从云端门户导出 .ampkg 包
    │
    ▼
通过 U 盘/内网传输至控制器可访问的终端
    │
    ▼
进入 App Center → 拖拽或点击上传 .ampkg
    │
    ▼
系统验证包签名（RSA）→ 解析元数据
    │
    ├─ 签名无效 → 拒绝，提示 "Invalid package signature"
    │
    └─ 签名有效 → 显示为 "Staged" 状态
         │
         ▼
    对应 App 行版本列显示 "Staged vX.X.X"
    操作按钮变为 "Apply"
         │
         ▼
    用户点击 "Apply" → 前置校验 → 创建快照 → 执行安装
         │
         ├─ 成功 → 版本更新，暂存包清除
         └─ 失败 → 快照恢复，暂存包保留
```

#### 2.3.5 交互说明

### 2.4 App 降级

#### 2.4.1 功能说明

将 App 从当前版本回退到上一个版本（仅支持回退一级）。降级基于升级前自动创建的快照恢复，不支持跨版本降级。

由于 App 降级是回退到旧版本，旧版本对底座的要求只会更低（不会更高），因此 App 降级不存在底座兼容性问题，无需校验底座版本。

#### 2.4.2 竞品功能设计及流程说明

| 竞品 | 实现方式 |
|------|----------|
| Cisco DNA Center | 不支持 App 级降级，仅支持整体回滚 |
| Aruba Central | 不支持降级 |
| VMware vCenter | 支持快照回滚，但非版本级别 |

AmpCon 差异点：App 级别精细降级，自动依赖校验，快照自动管理。

#### 2.4.3 功能业务流程

```
用户展开 App 版本历史
    │
    ▼
系统标记 "Previous" 版本（当前安装版本的下一个旧版本）
    │
    ▼
显示 "↩ Downgrade" 按钮（App 降级无底座兼容性问题）
    │
    ▼
用户点击 "↩ Downgrade"
    │
    ▼
弹出确认弹窗：
• 显示版本变化方向（vA → vB）
• 说明影响：恢复快照、回退配置、服务中断 ~30s
• 说明规则：仅一级、快照限制、DB schema 约束
    │
    ▼
确认 → 从快照恢复 → 刷新版本信息
```

> **设计说明**：App 降级不需要校验底座版本。旧版 App 对底座的要求只会更低，当前底座必然满足。

#### 2.4.4 原型界面

版本历史中的降级按钮：

```
█ v2.4.0 [Installed] ✓  2026-01-15
█ • Wireless AI optimization beta

┊ v2.3.0 [Previous]  2026-01-05    [↩ Downgrade]
┊ • Initial OTN device onboarding
```

降级确认弹窗：

```
┌──────────────────────────────────┐
│ Downgrade Campus Network         │
├──────────────────────────────────┤
│ v2.4.0  →  v2.3.0               │
│                                  │
│ ⚠ This will:                    │
│ • Restore previous version       │
│ • Revert config changes          │
│ • Service interruption ~30s      │
│                                  │
│ Downgrade Rules:                 │
│ • Only one version back          │
│ • Platform min-version enforced  │
│ • Cross-version not supported    │
│                                  │
│ [Cancel]  [↩ Confirm Downgrade]  │
└──────────────────────────────────┘
```

#### 2.4.5 交互说明

| 交互 | 说明 |
|------|------|
| "↩ Downgrade" 按钮 | 琥珀色，仅在 Previous 版本行显示 |
| 确认弹窗 "Confirm Downgrade" | 执行降级 |
| 确认弹窗 "Cancel" | 关闭弹窗，不执行 |

#### 2.4.6 列表字段

降级确认弹窗字段：

| 字段 | 说明 |
|------|------|
| 当前版本 | 降级前的版本号 |
| 目标版本 | 降级到的版本号 |

| 降级规则 | 仅一级、快照限制、DB 约束、底座依赖 |

#### 2.4.7 提示说明

| 场景 | 提示内容 | 类型 |
|------|----------|------|
| 降级成功 | "[App名] 已降级至 vX.X.X" | 成功 Toast |
| 降级失败 | "降级失败：[原因]" | 错误 Toast |
| 无快照可用 | "No pre-upgrade snapshot available. Downgrade not possible." | 错误阻止 |

#### 2.4.8 异常与容错处理

| 异常场景 | 处理方式 |
|----------|----------|
| 快照损坏 | 降级失败，保持当前版本，提示联系支持 |
| 降级中断电 | 重启后检测未完成操作，尝试完成恢复 |
| 降级后 DB 不一致 | 自动执行 DB 一致性检查和修复 |

#### 2.4.9 权限控制要求

| 操作 | 权限 |
|------|------|
| 查看降级按钮状态 | SiteAdmin / Viewer |
| 执行降级 | SuperAdmin |

#### 2.4.10 功能约束与边界

| 约束 | 说明 |
|------|------|
| 仅支持降级一个版本 | 快照仅保留最近一次升级前的状态 |
| 不支持跨版本降级 | DB schema 逐版本迁移，跨版本不可逆 |
| 无底座兼容性问题 | 旧版 App 对底座要求更低，当前底座必然满足 |
| 降级后快照清除 | 降级完成后，该快照被消费，无法再次降级 |

#### 2.4.11 非功能需求

| 项目 | 指标 |
|------|------|
| 降级执行时间 | ≤ 120 秒 |
| 服务中断时间 | ≤ 30 秒 |

### 2.5 App 卸载

#### 2.5.1 功能说明

从控制器中移除已安装的 App，包括其所有配置、数据和快照。卸载前需检查该 App 是否有活跃业务（在线设备、站点绑定、策略引用），有活跃业务时阻止卸载并引导用户完成清理。

#### 2.5.2 竞品功能设计及流程说明

| 竞品 | 实现方式 |
|------|----------|
| Cisco DNA Center | 不支持单独卸载 App |
| UniFi Network | 不支持卸载，仅支持禁用 |
| Meraki | SaaS 架构，无卸载概念 |

AmpCon 差异点：支持 App 级别卸载，带业务安全检查，阻止有活跃业务时的误卸载。

#### 2.5.3 功能业务流程

```
用户点击 App 行的垃圾桶图标
    │
    ▼
系统检查该 App 的活跃业务状态：
    │
    ├─ 活跃设备 = 0 且无站点绑定且无策略引用
    │   │
    │   ▼
    │   弹出确认弹窗（警告不可逆）
    │   │
    │   ├─ 确认 → 执行卸载 → 清理数据 → 刷新列表
    │   └─ 取消 → 关闭弹窗
    │
    └─ 活跃设备 > 0 或有站点绑定或有策略引用
        │
        ▼
        弹出阻止弹窗：
        • 显示活跃设备数量
        • 列出卸载前必须完成的 3 个步骤
        • 仅提供 "Understood" 关闭按钮
```

#### 2.5.4 原型界面

可卸载时的确认弹窗：

```
┌──────────────────────────────────┐
│ Uninstall AIDC Network           │
├──────────────────────────────────┤
│ ⚠ Are you sure?                 │
│ This removes AIDC Network and    │
│ all configuration. Cannot be     │
│ undone.                          │
│                                  │
│ [Cancel]        [🗑 Uninstall]   │
└──────────────────────────────────┘
```

有活跃业务时的阻止弹窗：

```
┌──────────────────────────────────┐
│ Uninstall Campus Network         │
├──────────────────────────────────┤
│ 🚫 Cannot Uninstall              │
│    — Active Business Running     │
│                                  │
│ 11 devices are running services  │
│ managed by this app.             │
│                                  │
│ Required before uninstall:       │
│ 1. Migrate/decommission devices  │
│ 2. Remove site bindings          │
│ 3. Clear active policies         │
│                                  │
│ [Understood]                     │
└──────────────────────────────────┘
```

#### 2.5.5 交互说明

| 交互 | 说明 |
|------|------|
| 垃圾桶图标 | 默认灰色，hover 变红色 |
| 确认弹窗 "Uninstall" | 红色按钮，执行卸载 |
| 阻止弹窗 "Understood" | 灰色按钮，仅关闭弹窗 |

#### 2.5.6 列表字段

卸载检查项：

| 检查项 | 数据来源 | 阻止条件 |

#### 2.5.8 异常与容错处理

| 异常场景 | 处理方式 |
|----------|----------|

#### 2.5.9 权限控制要求

### 2.6 网络状态检测

#### 2.6.1 功能说明

系统自动检测控制器与云端软件仓库的连通性，在界面顶部实时显示网络状态，并根据状态动态调整界面元素的显示和可用性。

#### 2.6.2 竞品功能设计及流程说明

大多数竞品不显式展示网络状态，AmpCon 通过明确的状态指示器让管理员清楚当前环境能力。

#### 2.6.3 功能业务流程

```
页面加载 → 发起连通性探测（HTTPS HEAD 请求）
    │
    ├─ 成功 → 设置为 "Cloud Connected"
    │         → 拉取云端版本信息
    │         → 上传区域显示为紧凑样式
    │
    └─ 失败/超时 → 设置为 "Offline Mode"
                  → 云端版本列显示 "N/A"
                  → 上传区域放大突出
                  → 升级按钮变为 "Upload"
```

#### 2.6.4 原型界面

在线状态：
```
┌──────────────────────────────────────────────┐
│ ● Cloud Connected                  [Refresh] │
│ Connected — Latest versions fetched          │
└──────────────────────────────────────────────┘
```

离线状态：
```
┌──────────────────────────────────────────────┐
│ ⚠ Offline Mode                               │
│ Cannot reach cloud. Upload .ampkg packages.  │
└──────────────────────────────────────────────┘
```

#### 2.6.5 交互说明

| 交互 | 说明 |
|------|------|
| 状态指示器 | 绿色圆点=在线，琥珀色三角=离线 |
| "Refresh" 按钮 | 手动重新检测连通性 |
| 状态切换 | 自动刷新界面，版本信息和按钮状态联动更新 |

#### 2.6.6 列表字段

无独立列表。

#### 2.6.7 提示说明

| 场景 | 提示内容 | 类型 |
|------|----------|------|
| 从离线恢复在线 | "Cloud connection restored. Refreshing versions..." | 信息提示 |
| 从在线变为离线 | "Cloud connection lost. Switching to offline mode." | 警告提示 |

#### 2.6.8 异常与容错处理

| 异常场景 | 处理方式 |

## 3. 版本依赖矩阵

### 3.1 App 最低底座版本要求

依赖关系是单向的：**App 依赖底座**。每个 App 版本声明自己所需的最低底座版本（类似手机 App 要求最低 iOS 版本）。

| App | App 版本 | 要求底座 ≥ |
|-----|---------|-----------|
| Campus Network | v2.6.0 | v2.5.0-LTS |
| Campus Network | v2.5.0 | v2.4.0-LTS |
| Campus Network | v2.4.0 | v2.3.0-LTS |
| Security & Surveillance | v2.1.0 | v2.0.0-LTS |
| AIDC Network | v2.4.0 | v2.5.0-LTS |
| AIDC Network | v2.3.0 | v2.4.0-LTS |
| AIDC Network | v2.2.0 | v2.3.0-LTS |
| IDC Network | v2.6.1 | v2.5.0-LTS |
| IDC Network | v2.5.0 | v2.4.0-LTS |
| Transport Network | v2.3.0 | v2.4.0-LTS |
| Transport Network | v2.2.0 | v2.3.0-LTS |

### 3.2 各操作的校验规则

| 操作 | 校验规则 | 说明 |
|------|----------|------|
| 底座升级 | 无 App 相关校验 | 底座不依赖 App，直接升级。高版本底座 API 向后兼容旧 App |
| 底座降级 | 检查已安装 App 的最低底座要求 | 若某 App 要求底座 ≥ vX，而降级目标 < vX，则警告该 App 可能无法运行 |
| App 升级/安装 | 检查新 App 版本要求的最低底座版本 | 若当前底座版本 < App 要求，阻止安装并提示 "Requires platform ≥ vX.X.X" |
| App 降级 | 无底座校验 | 降级到旧版 App，其底座要求只会更低，不会有兼容问题 |
| App 卸载 | 无版本依赖 | 仅检查活跃业务 |

## 4. .ampkg 包格式规范

| 区段 | 内容 | 说明 |
|------|------|------|
| Header (64B) | Magic Number + Format Version + SHA-256 Checksum | 包完整性校验 |
| Metadata (JSON) | type: platform/app, appId, targetVersion, minPlatformVersion, size | 自动解析用 |
| Payload | 压缩镜像 + DB 迁移脚本 + 配置模板 | 实际安装内容 |
| Signature (RSA) | 厂商私钥签名 | 来源和完整性验证 |
